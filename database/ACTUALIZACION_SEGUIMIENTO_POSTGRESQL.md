# Actualización de seguimiento — PostgreSQL

Autorizada y aplicada en PostgreSQL local el 01/10/2026. Se verificaron columnas, PK, FK, restricciones e índices. Para otra instalación existente, aplicar este script una sola vez; no ejecutar el instalador completo contra la base existente. No se insertan eventos ni se reconstruyen fechas/autores históricos desconocidos. SQL Server no se ejecutó.

La definición canónica es DATABASE.md; este script de actualización reproduce exclusivamente su bloque TicketEvents y añade la clave compuesta necesaria a Evidences para garantizar que una foto vinculada pertenezca al mismo ticket. No hay columnas nuevas en Tickets/Evidences, triggers, funciones, vistas ni datos demo. Las FK son restrictivas.

Revisar previamente que TicketEvents y UQ_Evidences_TicketId_Id no existan. Este script se ejecuta una sola vez: si ya se aplicó, no repetirlo; un error revierte la transacción, sin borrar datos. IF NOT EXISTS no transforma una tabla preexistente incompatible.

```sql
BEGIN;

ALTER TABLE public."Evidences"
    ADD CONSTRAINT "UQ_Evidences_TicketId_Id" UNIQUE ("TicketId", "Id");

CREATE TABLE IF NOT EXISTS public."TicketEvents" (
    "Id" integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    "TicketId" integer NOT NULL REFERENCES public."Tickets" ("Id") ON DELETE RESTRICT,
    "EventType" varchar(20) NOT NULL,
    "Description" text NOT NULL,
    "CreatedAt" timestamptz NOT NULL,
    "UserId" integer NOT NULL REFERENCES public."Users" ("Id") ON DELETE RESTRICT,
    "ClientRequestId" uuid NOT NULL,
    "PreviousScheduledAt" timestamptz NULL,
    "ScheduledAt" timestamptz NULL,
    "EvidenceId" integer NULL,
    CONSTRAINT "UQ_TicketEvents_UserId_ClientRequestId" UNIQUE ("UserId", "ClientRequestId"),
    CONSTRAINT "FK_TicketEvents_Evidences" FOREIGN KEY ("TicketId", "EvidenceId")
        REFERENCES public."Evidences" ("TicketId", "Id") ON DELETE RESTRICT,
    CONSTRAINT "CK_TicketEvents_EventType" CHECK (
        "EventType" IN ('CREADO', 'PROGRAMADO', 'REPROGRAMADO', 'EN_ATENCION', 'SEGUIMIENTO', 'RESUELTO')),
    CONSTRAINT "CK_TicketEvents_Description" CHECK (
        length(btrim("Description")) > 0 OR ("EventType" = 'SEGUIMIENTO' AND "EvidenceId" IS NOT NULL)),
    CONSTRAINT "CK_TicketEvents_Evidence" CHECK ("EvidenceId" IS NULL OR "EventType" = 'SEGUIMIENTO'),
    CONSTRAINT "CK_TicketEvents_Schedule" CHECK (
        ("EventType" = 'PROGRAMADO' AND "PreviousScheduledAt" IS NULL AND "ScheduledAt" IS NOT NULL)
        OR ("EventType" = 'REPROGRAMADO' AND "PreviousScheduledAt" IS NOT NULL
            AND "ScheduledAt" IS NOT NULL AND "PreviousScheduledAt" <> "ScheduledAt")
        OR ("EventType" NOT IN ('PROGRAMADO', 'REPROGRAMADO')
            AND "PreviousScheduledAt" IS NULL AND "ScheduledAt" IS NULL))
);

CREATE INDEX IF NOT EXISTS "IX_TicketEvents_TicketId_CreatedAt_Id"
    ON public."TicketEvents" ("TicketId", "CreatedAt", "Id");

COMMIT;
```

El índice UNIQUE no modifica filas: Id ya es único. TicketEvents empieza vacía. No se necesita un backfill ficticio; los registros antiguos mantienen su información original. El runtime actual no se modifica ni utilizará esta tabla hasta una etapa posterior autorizada.

Diseño de autoría, foto opcional, SQLite y sincronización: sección TicketEvents de DATABASE.md. La API valida que un seguimiento sin descripción tenga una fotografía persistida del mismo ticket; un EvidenceId por sí solo no demuestra su contenido.
